# /commit - 規約準拠コミット

直近の変更を確認し、既存案件の慣習と `rules/git-conventions.md` に沿ってコミットする。

## 手順

1. `git status` と `git diff --cached` / `git diff` で変更範囲を確認する。
2. 変更が複数目的にまたがる場合は、分割の必要性を先に指摘する。
3. 既存プロジェクトのコミット履歴に明確な慣習がある場合はそれを優先する。
4. 既存ルールがなければ、prefix なしで「何をどう変えたか」が分かる具体的な日本語メッセージを提案する。
5. 秘密情報や意図しないファイルが混ざっていないかを確認する。
6. ユーザー承認後に必要なファイルだけを対象にコミットする。

## 注意

- 1コミット1目的を崩さない。
- `修正` や `fix` のような曖昧なメッセージを避ける。
- コミット実行前に対象ファイル一覧を明示する。

## 自然文の例

- `コミットして`
- `規約どおりにコミットして`
- `変更を記録して`

## 出力

- 対象ファイル一覧
- 提案コミットメッセージ
- 分割が必要な場合はその提案
- 次に push すべきかどうか
